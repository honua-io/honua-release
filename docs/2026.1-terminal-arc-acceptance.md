## Concrete release-harness gap

At the audited release revision, `stages.py` returns unconditional blocked checks
for service mutation, style pixels, GP execution, composition persistence,
publication and approval. `live_driver.py` likewise blocks `execute`,
`inject_error`, `approve` and final verification. Closing server issues cannot
make these adapters execute. This is pre-cut implementation work under #123,
not an exact-candidate exception and not proof that current server contracts are
absent. The existing immutable receipts remain unedited.

This delivery corrects one reproducible contradiction: the installed command
surface can prove `honua admin` present while stages 2/3/8 report it absent.
New checks consume the verified per-run command result and reject missing,
ambiguous or unsuccessful verification. They record discovery separately from
execution and still block on the missing credential/mutation/approval probes.
The `--help` check rejects a process that advertises `admin` but exits nonzero.

Focused validation: `python3 certification/terminal-journey/test_run.py -v`
passes 41 tests, including a real Node child-process fixture with independently
declared exit codes 0 and 2, plus missing/ambiguous verification and
discovery-without-execution rejection. This is client/receipt correctness
evidence only; it supplies no GP geometry, render pixels or live publication
receipt. The future GP proof must compare independently calculated expected
geometry/ordinates and metadata, and both saved compositions must refer to that
verified output.
