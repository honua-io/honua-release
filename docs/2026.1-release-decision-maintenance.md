| Input / policy | Rule |
|---|---|
| `2026.1-release-decision-inputs.json` | Timestamped sanitized issue metadata, body hashes, immutable dispatch packet references, implementation issue states. Never raw bodies, credentials or secret material. |
| `2026.1-release-decision-overrides.json` | Every scope/sequence exception has a reason; admission reviews bind to the reviewed body hash. A changed or new P1/first-release-gate body without a review fails before any label write. Review the body in GitHub, then record whether it names a security/isolation floor, data corruption/silent wrong data, or a broken documented supported workflow. |
| Rule precedence | Explicit canonical scope/sequence exceptions; every remaining P0; admitted first-release-gate; feature/3D/later-release labels; P1 assigned hunt family or named promise; other P1/P2/P3/unprioritized hardening. Scope exceptions distinguish feature expansion from required GA gate machinery. |
| Candidate-only P0 overlap | Decision 5 places server#3849 and #3381/#3805 overlay after cut; the alerting Preview ruling removes #3861. These explicit exceptions retain P0 labels and reasons; other P0s stay before cut. The 2026-09-29 Preview amendment (ruling R3, [studio#2](https://github.com/honua-io/honua-studio/issues/2#issuecomment-5883905244)): a P0 on a Preview surface is not a cut blocker unless it is a security, isolation or integrity floor. It is applied only as a per-issue exception with its reason (studio#2, #26, #41); the classifier's P0 default is unchanged, so an unreviewed Preview P0 stays before cut. |
| Ruling-driven moves | An exception that a ruling causes names it in `ruling` (for example `R28` for every executable-docs finding), and the `rulings` block lists each ruling with its authority, the issues it moved, and its effect. A ruling that moves nothing records `moved: []`. The security-review disposition is cited by counts and public `SEC-N` ids only; the findings stay on the private tracker. |
| Decision | Computed, never hand-set: `GO` only when no open issue is `must-fix-before-cut`, every `security_findings` row is `fixed`, and the inputs carry a `signed_lock` (`tag` `2026.1-rc.N`, `sha256` `digest`). Otherwise `HOLD`, with each unmet condition named in the header. |
| GA-blocking security findings | `security_findings` holds one public row per GA-blocking finding: `{"id":"SEC-N","repo":"honua-io/<repo>","status":"open"}`, or `"status":"fixed"` with `"fixedBy":"<PR number>"`. Detail stays on the private tracker. Flip a row to `fixed` only after the tracker closes the finding. The row count must equal the ruling's `ga_blocker` count. `gate-security-findings` checks that each fixed row's PR is merged to the default branch and cites its id, and that the record carries the computed Decision. Any failure, including an unreadable PR, fails the gate. |
| Working-candidate train | `working_candidate.train_kind` names what produced the observation (`dry-run`, `scheduled strict` or `dispatched strict`); the header renders `<kind> train`. A missing or unknown kind fails regeneration. |
| Label lag | `--check` verifies the snapshot's live labels against the decided buckets. A `--refresh` that admits issues without a matching `bucket/*` label therefore fails `--check`, and `validate` with it, until the coordinator runs `--refresh --apply` and commits the re-observed snapshot. |
| One bucket | Add exactly one of the four `bucket/*` labels and remove competing bucket labels; preserve unrelated labels. `2026.2` also gains `release/2026.2` and loses `release/2026.1`. |
| First-release-gate admission | Unnamed promises default to hardening and lose the gate with a one-line comment citing the 2026-09-04 rule. Superseded scope gates lose the label with their explicit ruling reason. Comments have an idempotency marker. |
| Retained cohort | Fetch all org repositories with pagination; exclude PRs. Previously captured issues remain tracked after moving to 2026.2 or closing. Counts show open cohort members, including moved items; closed rows remain in the ledger. New live release issues join the cohort. |
| Ownership | Packet links use an immutable honua-flow revision. Queued, parked and dispatched are distinguished; dispatched is not proof of current execution. Refresh packet references after verifying the dispatch queue. No matching delivery packet means UNOWNED. |
| Implementation vs qualification | Issue closure changes only the implementation column. No ticket closure can make qualification green. Until the cut: `not yet cut`; afterward a digest alone still means `not proven; gate receipts required`. Gate-consumed receipts and independent approvals determine GA. |
| Publishing | Post the generated two tables on release#268; the pinned issue links the trunk record plus the review PR until merged. Refresh the snapshot before promotion; this decision record cannot promote a release or waive a gate. |
| Burn-down | Every `--refresh` adds the day's open counts per bucket to `2026.1-release-burndown.jsonl`, one line per UTC day of `observed_at`. A second refresh on the same day replaces that day's line, so reruns never add points. Commit the file with the refreshed inputs. The 2026-09-11 and 2026-10-04 points were taken from the ledgers committed on those days. |
| Release dashboard | `publish-dashboard` publishes `site/index.html` to GitHub Pages when a push to trunk changes the inputs, overrides, burn-down or renderer, and on `workflow_dispatch`. The page uses the record's ticket set, buckets, repository list and computed Decision. It shows a ticket the rules cannot classify as unbucketed instead of failing. In-flight coverage means an open PR whose body closes the ticket with a GitHub closing keyword. Each covering PR is shown with its `mergeStateStatus`. A ticket with no covering PR is `uncovered` if its repository was readable, otherwise `not observed`. Age counts days from `created_at` to the observed day; rows captured before inputs carried `created_at` show `—` until the next refresh. The page is public (R30): ticket titles appear as recorded, private repositories are never linked, security findings appear only as `SEC-N` ids, and PR titles and bodies are never shown. |
| Network | Same-command backoff has a shared five-minute sleep budget for transient failures and HTTP 403 responses. HTTP 403 sleeps up to 60 seconds before retrying; exhaustion fails with an error. Never re-authenticate. |
