SDK producer revisions frozen in its manifest, using one immutable requirements

## Remaining acceptance criterion

Released criterion in the delivery PR, because it requires the new exact
candidate: finish the source/catalog
convergence, re-aggregate the ledger against the staged honua-release commit,
and activate `PROTOCOL_CERTIFICATION_MATRIX_COMMIT`,
`PROTOCOL_CERTIFICATION_MATRIX_SHA256`, and
`PROTOCOL_CERTIFICATION_REQUIREMENTS_SOURCE_REVISION` together. Issue #181 stays
open in its existing must-fix-before-cut bucket until disposition is reconciled
by the release owner. This is not evidence of qualification.

This criterion requires the new freeze's exact published SDKs and candidate
image: the current Python artifact predates the mandatory producer contract,
and there is no complete ledger for the current denominator. Preserve the
freeze-at-cut rule and published artifact identities. At cut:

1. Select published SDK revisions containing their certification contracts and
   bind the manifest to those artifact identities. Select the new server image
   and run the required producers in trusted trunk context for that candidate.
   Recheck the gRPC/MCP producer-side image pins required by #181's checklist.
2. Run `convergence-rebind.yml` in PLAN mode, then APPLY after the sources and
   producer evidence exist. APPLY stages a regenerated catalog, dispatches
   aggregation for that exact staged commit and candidate triple, verifies the
   ledger digest, and finalizes a single review PR with the three gate pins.
3. Merge that rebind PR with a merge commit so the staged requirements commit
   remains reachable. `convergence-rebind-activate.yml` verifies ancestry and
   ledger identity, then copies all three coordinates from the merged manifest.
   Verify those variables and the strict evaluator on the resulting head.
