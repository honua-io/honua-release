# Lambda GA bill — evidence ledger (release#282, ruling A)

State of the evidence as of **2026-09-07 (UTC)**. Nothing in this document is a
pass. **No passing Lambda certification receipt exists**: twelve live runs of the
certification lane have completed, all twelve recorded `result: fail` and
`serving.result: noProof`, and Lambda therefore remains
`status: ga-target` / `qualification: pending` in
[`platform-manifest.yaml`](../platform-manifest.yaml).

**Why this file exists.** The [operator ruling A of 2026-09-06](https://github.com/honua-io/honua-release/issues/282)
promoted AWS Lambda from Preview to a 2026.1 **GA target** carrying the whole ECS
bill (live deploy, serving smoke, upgrade, rollback, destroy) on the real
serverless substrate, and the amendment is recorded in the
[quality contract](https://github.com/honua-io/honua-flow/blob/trunk/docs/2026.1-quality-contract.md).
The bill's five items are already enforced from three places — the
[cut checklist](RELEASE-CUT-CHECKLIST.md), the generated
[decision record](2026.1-release-decision-record.md), and the
[serverless operating envelope](2026.1-operating-envelope.md#5-aws-lambda-serverless-supported-target-and-limits)
with the manifest qualification gate behind it. What none of those carry is the
*current position*: which live evidence exists today, what it says, and what is
still missing. That is what this ledger records, and only that. It changes no
gate, grants no qualification, and cannot be cited as a receipt.

**What discharges the bill.** A passing certification receipt, produced by the
lane below, meeting the acceptance rules already written into the
[cut checklist](RELEASE-CUT-CHECKLIST.md) rows for
[release#282](https://github.com/honua-io/honua-release/issues/282). Only then do
the `supported` / `passed` / `qualificationReceipt` values described in the
[operating envelope](2026.1-operating-envelope.md#5-aws-lambda-serverless-supported-target-and-limits)
become declarable, and only then does release#282 close.

**Run 12 is the furthest the lane has reached, and it is still a fail.** The
lane owner reports in [honua-server#4490](https://github.com/honua-io/honua-server/pull/4490)
that this run is the first in which the ephemeral function answered the health
probe with 200 and a healthy body, after the substrate gained the secrets-read
grant and a policy-compliant admin password. **That statement is the lane
owner's, not a receipt**: run 12's own receipt records `result: fail` and
`serving.result: noProof`, the serving assertions of bill item 2 did not
execute, and this repository records no serving pass.

Cause of the run-12 failure, per the same PR: server initialization takes about
21 s on this substrate (Secrets Manager resolution plus the database connection
over the VPC), which exceeds Lambda's init window, so the runtime re-runs init
inside the first invoke and the only `Init Duration` appears on an
`INIT_REPORT … Phase: invoke` line rather than on `REPORT`. The fix reads the
value from either line, still fails closed when neither carries a positive
value, and records which phase supplied it. That ~21 s init is itself an
operating-envelope fact for the [cold-start row](2026.1-operating-envelope.md#5-aws-lambda-serverless-supported-target-and-limits);
it is not yet a certified measurement.

## 4. What is blocking, right now

1. **honua-server [#4490](https://github.com/honua-io/honua-server/pull/4490) (open)** — the cold-start parse fix. Run 13 follows its merge.
2. **honua-iac [#175](https://github.com/honua-io/honua-iac/pull/175) (open, already applied)** — the substrate the last runs used is ahead of iac trunk. Until it merges, the certification account's state is not reproducible from a merged revision, and a fresh apply from trunk would not reproduce runs 10–12.
3. **Bill item 2 has never executed.** Reaching a passing receipt means the lane must get past the cold-start parse and then actually run the fixture row-count, write round-trip, denial and executed-version assertions against the cert PostGIS fixture.
4. **Items 3 and 4 cannot start** until a candidate exists; they are correctly parked in the `prove-against-candidate` bucket.

Nothing here is dispatched from this repository. Certification runs, AWS access,
and changes to honua-server or honua-iac belong to those lanes.

## 5. When the bill closes

Discharge, in order:

1. A green run of the lane on trunk's Lambda digest, with a receipt naming the exact source and ECR digests, executed serving assertions and cleanup outcomes → items 1 and 2, and the candidate cut is unblocked.
2. The same lane re-run against the exact candidate, with alias-shift upgrade and rollback through the deploy backend and full teardown → item 3.
3. Manifest re-pin from the real ECR mirror and `contractVersions` re-read from the booted candidate → item 4.
4. Only then: `status: supported`, `qualification: passed`, and a `qualificationReceipt` whose `url` is that run and whose `candidateManifestDigest` is computed by `qualification_candidate_digest` over the exact manifest → item 5 completes and [release#282](https://github.com/honua-io/honua-release/issues/282) closes.

Any candidate-affecting change invalidates the binding and requires fresh proof.

## 6. Reproducing this ledger

Read-only; requires `gh` authenticated against the honua-io org. No AWS access
is needed and none should be used from this repository.

```bash
# the twelve runs and their conclusions
gh run list -R honua-io/honua-server \
  --workflow lambda-preview-certification.yml -L 20 \
  --json databaseId,createdAt,headSha,conclusion

# the receipt a given run produced
gh run download <run-id> -R honua-io/honua-server -D ./receipt
cat ./receipt/lambda-preview-certification-receipt/lambda-preview-receipt.json

# the lane's own contract, including the receipt schema
gh api repos/honua-io/honua-server/contents/scripts/cloud/lambda-certification.md \
  -H 'Accept: application/vnd.github.raw'

# the manifest's current Lambda declaration
python3 tools/validate_platform.py --exact-candidate   # expected: fails closed while qualification is pending
```
