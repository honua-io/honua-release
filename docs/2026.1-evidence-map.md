## What the GA scope is

The authority is the [quality contract in `honua-flow`](https://github.com/honua-io/honua-flow/blob/8d5ae137efc0ca460afaf529f9fe390d949febc3/docs/2026.1-quality-contract.md) §14 plus every AMENDMENT line at the audit date, as adopted on release#210. For this packet that means:

- **GA:** core PostGIS-backed serving, auth/RBAC/isolation floor, selected OGC and GeoServices profiles, the **whole** `BuiltInProcessCatalog` (2026-09-04 reaffirmation, no per-operation carve-out), and **all four cloud-native formats** — COG, Zarr, GeoParquet, PMTiles (2026-09-04 decision 3). STAC and OGC API Records stay GA as the catalog surface.
- **Preview, isolation floor retained at full severity:** multi-tenancy (single-tenant is the GA posture), customer alerting, offline sync (`createReplica` / `synchronizeReplica` / `extractChanges`), ImageServer + its WMTS, OGC API EDR, OGC API Coverages, NAServer, VersionManagementServer.
- **Preview-tier evidence:** the SDK release certification lane (HTTP dev server, base seed); release-tier client evidence still needs the TLS + canonical-fixture overlay.

## Schema

Row data follows [`schemas/2026.1-evidence-map.schema.json`](../schemas/2026.1-evidence-map.schema.json). Each row is one GA operation-and-configuration claim, with five columns:

| Column | Meaning |
|---|---|
| **Contract** | operation · protocol · supported configuration · edition · principal. The exact thing we promise, for a named caller. |
| **Expected behaviour** | the exact result, the durable side effects, and the failure behaviour. |
| **Proof** | the responsible tests by path and test name, the fixture, the **execution layer**, and whether a **candidate-bound receipt** exists. |
| **Gaps** | untested behaviours, skipped cases, weak assertions, and evidence claims the tests do not support. |
| **Disposition** | keep / strengthen / consolidate / move / remove / not yet reviewed. |

**Execution layers** (the contract's five): `unit` · `api-integration` (API/HTTP integration, in-process or out-of-process; backing stores may be real or fake and are stated separately in each proof) · `published-container-e2e` · `emulator` · `real-ecs`.

**Candidate-bound receipt** means the evidence records the immutable candidate identity (image digest / lock) together with the required fixture and behaviour result. A passing local test, a scheduled workflow, a source SHA, or an API-surface inventory is **not** a receipt. In this packet the answer is `no` for every row; part 2 does not change that, because no pre-cut candidate exists yet.

**Structured representation:** `disposition` is a non-empty array of unique vocabulary values. An empty `proof.tests` requires `noProof: true`; populated tests forbid that state. A test with `candidateBoundReceipt: true` requires a `receipt` with an `imageDigest` or `lockSha256`, plus `fixtureSha256`, `resultSha256` and `result` (`pass`, `fail` or `skipped`). Each digest uses `sha256:` followed by 64 lowercase hex characters. These identify the candidate, fixture and behavior-result artifacts; consumers must retrieve and verify them. Schema validation alone neither authenticates evidence nor certifies a candidate.

**Disposition vocabulary:**

- **keep** — the test proves its contract row; leave it alone.
- **strengthen** — the behaviour is real and the test is pointed at it, but the assertion does not prove it. Never a deletion: a weak assertion on a critical behaviour is always strengthened.
- **consolidate** — several tests cover the same ground and one of them is the honest one; fold the others into it.
- **move** — the proof exists at the wrong layer (a unit seam standing in for a protocol round-trip, or vice versa).
- **remove** — the test asserts nothing about the product. Used once in this packet, on the operator's explicit 2026-09-04 ruling (a).
- **not yet reviewed** — inside scope but not read in this packet. Listed again under Coverage limits.

## Three facts that bound almost every row below

These were established from source, and they change how much most protocol tests prove. They are stated once here and referenced by rows rather than repeated.

**(F1) The integration fixture runs with authentication disabled by default.**
`tests/dotnet/Honua.TestKit/Mixins/WebAppFixturePostgresWiringMixin.cs::ApplyCommonHostSettings` sets `HONUA_DEV_AUTH=true` and `HONUA_DEV_AUTH_ALLOW_BYPASS=true` on **every** `WebAppFixture` host, shared and isolated alike (`WebAppFixtureSharedBootstrapMixin.cs` repeats it for the shared factory). In `src/Honua.Hosting/Features/Authentication/ApiKeyAuthenticationHandler.cs`, `HandleAuthenticateAsync` short-circuits on that bypass and returns a successful `"dev-bypass"` principal **before any credential is read**. A fixture opts back into real authentication by calling `ConfigureWebHost(b => b.UseSetting("HONUA_DEV_AUTH", "false"))`, which runs after `ApplyCommonHostSettings` and wins.

The numbers on trunk: **483** test files use `WebAppFixture`; **138 opt-out sites across 111 files**. Across the seven `Honua.Protocols.*.Tests` projects, 206 files use the fixture and 17 opt out; across the four core protocol projects it is 181 fixture files and **6** opt-outs (GeoServices 85/0, OgcApi 47/3, OgcClassic 20/1, OData 29/2). `Honua.Protocols.GeoServices.Tests` still has **zero** opt-outs; `Honua.Protocols.OgcClassic.Tests` gained its first one after this audit's first pass (`Wfs20EndpointsTests.cs:1125-1126`, [#4192](https://github.com/honua-io/honua-server/pull/4192)). Consequence: the large majority of protocol tests prove **functional behaviour only** and prove nothing about authorization, and a test on a non-opted-out fixture whose name says "Anonymous" is describing a client that is in fact authenticated. Rows below name the fixture so the distinction is never guessed.

**(F2) The fixture that does prove authorization does not touch the database.**
`tests/dotnet/Honua.TestKit/Helpers/ServiceRbacTestFixture.cs` sets `HONUA_DEV_AUTH=false` and installs a header-driven `TestAuthHandler`, so its decisions are real. But it builds on `TestWebApplicationFactory`, which replaces `IFeatureReader`/`IFeatureWriter`/`ITileProvider`/`IStreamingFeatureStore` with the in-memory `tests/dotnet/Honua.TestKit/Infrastructure/TestFeatureStore.cs`. Consequence: authorization is proven at the endpoint/middleware layer against a fake store. No test proves that a denied principal is refused **records that actually exist in PostGIS**.

**(F3) The required per-PR check does not run the integration suite.**
`.github/workflows/pr-gate.yml` and `.github/actions/lean-gate/action.yml` run five test steps: `Honua.Server.Tests --filter "Tier=Fast"` (`:238`), `Honua.Architecture.Tests` (`:254`), two named MCP classes in `Honua.Ai.Tests` (`:274`), `Honua.Server.Tests --filter "Category=Architecture"` (`:296`), and — added by [#4378](https://github.com/honua-io/honua-server/pull/4378) after this audit's first pass — `Honua.Worker.Gdal.Tests --filter 'Category=RasterExecutionProof'` against the production GDAL image (`pr-gate.yml:228-240`), plus a boot/migrations smoke. **No `Honua.Protocols.*.Tests` project runs on the required gate**, so everything below marked `api-integration` still runs only in the trailing full matrix (`ci.yml` has no `pull_request` trigger). That is the adopted eventual-quality landing model and is not itself a defect — but outside the raster-proof step, "the gate is green" never implies any row below is proven.

## Priority 3 (continued) — Geoprocessing: the whole `BuiltInProcessCatalog`

## Weak-assertion patterns found, as a checklist

Recorded so part 2 and the burn-down can grep for them rather than rediscover them.

- Accepting refusal alongside success — `BeOneOf(OK, Unauthorized)`, `BeOneOf(OK, Accepted, Unauthorized)`.
- Accepting a server error as a pass — `BeOneOf(Created, ServiceUnavailable, InternalServerError)`.
- `NotBe(Forbidden)` / `NotBe(Unauthorized)` / `NotBe(NotFound)` in place of an exact status.
- Shape-only — "the response has a `features` array", `NotBeEmpty()`, magic bytes (`PAR1`, PNG signature, `II`/`MM`).
- Denial asserted by status alone, with no state or disclosure check.
- Echo-only mutation assertions with no read-back.
- Filtering asserted by a per-row re-check of the same predicate, proving no false positives but never no false negatives.
- Vacuous pass — a `foreach` with no non-empty precondition, or an early `return` on an empty fixture.
- Assertions on a method the production code cannot call (`DidNotReceive().SetAsync` where only `TrySetAsync` exists).
- A test name that promises behaviour the body never exercises (`…SupportsAtomicity` with no failing member; `…RecoversAcrossRestart` with no restart; `…ConcurrentOperations…` with disjoint keys; `…ReconcilesAgainstSource` with a magic-byte check).
- Sequential awaits standing in for concurrency.
- Fixtures that make the assertion circular — a fake runner that writes the test's own bytes; a fake store that returns hardcoded content when nothing was written; a hand-authored tool stdout parsed back as if measured.
- Silent skips — `pytest.skip` on a 404/501, `Skip` when a binary is absent, `describe.skip` when an env var is unset, `[RequiredEnvironmentFact]` with no counts tripwire.
- `[Endpoint]`/`[Operation]` annotations on tests that never issue a request (all 15 in `FileUploadSecurityTests.cs`).

## Weak-assertion patterns — part 2 additions

- **A tautological comparison** — `response.Count.Should().BeGreaterOrEqualTo(0)` on an unsigned count (R-19); `Contain("\"featureCount\":")`, which asserts a key with no value (R-11); `TryGetProperty("success", out _).Should().BeTrue()`, which passes on `{"success": false}` (R-07).
- **An assertion behind a guard that cannot be true** — `if (response.StatusCode != HttpStatusCode.OK) { … NotContain("StackTrace") … }` on a surface documented to always return 200 (R-03).
- **A mock that returns the same answer for every input**, so a positional or coordinate query cannot be wrong (R-04: constant band values at every coordinate; R-05: a constant extent regardless of the requested clip).
- **A fixture in which the feature under test cannot act** — a `datetime` filter tested against records that all have `Modified: null`, with the assertion written as "must not exclude" (R-02).
- **Skipping on the condition under test** — `Skip.If(summary.Status is …Valid, "the pinned server image's validation did not reject …")`, so a server that stops validating turns the test green (R-12).
- **Skipping because the fixture disabled the control being tested** — the console's anonymous-leak assertion is skipped precisely because the lane runs with the dev-auth bypass on (R-12).
- **A gate that compares an artifact with itself** — the import-fidelity scorecard governance step passes the same baseline path as both arguments (R-09).
- **A lane whose failures are discarded and whose results are unmapped** — `|| true` plus a deliberate exclusion from the baseline diff (R-09).
- **A qualification workflow that validates a receipt instead of running a test**, including one that consumes an artifact no workflow produces (R-14) and one that verifies a self-reported artifact from another repository (R-15).
- **A stand-in substrate presented as the thing itself** — busybox as "revision A and B" of an application upgrade (I-05); nginx as the ECS service under a "live certification" (I-07); a PostGIS container as Redshift (R-17).
- **A synthetic payload that is not a valid instance of the format it is labelled** — `{0x01,0x02,0x03,0x04}` as an MVT, ASCII `TPKX` as a TPKX, `"RASTER-TILE-BYTES"` served as `image/png` (R-10).
- **A meta-test that greps the script it certifies** — `scripts/cloud/test-certify-lambda-preview.py`, `e2e/dr-drill/test_contract.py` (I-06, I-09).
- **Documentation that promises an artifact the repository does not contain** — per-migration rollback scripts (I-01); a Studio container and tarball (R-13); CITE lanes for six capabilities (F7).
