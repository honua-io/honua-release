# 2026.1 GA evidence map — part 1

Owner: [release#210](https://github.com/honua-io/honua-release/issues/210) · audit run 2026-09-05 · scope: priorities 1–3 (authorization and data disclosure; mutations, transactions, concurrency and recovery; geospatial correctness and the four cloud-native formats). Part 2 appends the remaining areas to this same document.

This is a **defensive review of what our own tests prove**, not a test inventory. It was produced by reading test bodies, fixtures and the code under test — never by trusting a test name, an `[Endpoint]` annotation, a workflow name, or a green run.

## What the GA scope is

The authority is `docs/2026.1-quality-contract.md` §14 plus every AMENDMENT line, as adopted on release#210. For this packet that means:

- **GA:** core PostGIS-backed serving, auth/RBAC/isolation floor, selected OGC and GeoServices profiles, the **whole** `BuiltInProcessCatalog` (2026-09-04 reaffirmation, no per-operation carve-out), and **all four cloud-native formats** — COG, Zarr, GeoParquet, PMTiles (2026-09-04 decision 3). STAC and OGC API Records stay GA as the catalog surface.
- **Preview, isolation floor retained at full severity:** multi-tenancy (single-tenant is the GA posture), customer alerting, offline sync (`createReplica` / `synchronizeReplica` / `extractChanges`), ImageServer + its WMTS, OGC API EDR, OGC API Coverages, NAServer, VersionManagementServer.
- **Preview-tier evidence:** the SDK release certification lane (HTTP dev server, base seed); release-tier client evidence still needs the TLS + canonical-fixture overlay.

## Schema

Row data follows [`schemas/2026.1-evidence-map.schema.json`](../schemas/2026.1-evidence-map.schema.json). Each row is one GA operation-and-configuration claim, with five columns:

| Column | Meaning |
|---|---|
| **Contract** | operation · protocol · supported configuration · edition · principal. The exact thing we promise, for a named caller. |
| **Expected behaviour** | the exact result, the durable side effects, and the failure behaviour. |
| **Proof** | the responsible tests by path and test name, the fixture, the **execution layer**, and whether a **candidate-bound receipt** exists. |
| **Gaps** | untested behaviours, skipped cases, weak assertions, and evidence claims the tests do not support. |
| **Disposition** | keep / strengthen / consolidate / move / remove / not yet reviewed. |

**Execution layers** (the contract's five): `unit` · `api-integration` (real PostGIS/Redis in-process) · `published-container-e2e` · `emulator` · `real-ecs`.

**Candidate-bound receipt** means the evidence records the immutable candidate identity (image digest / lock) together with the required fixture and behaviour result. A passing local test, a scheduled workflow, a source SHA, or an API-surface inventory is **not** a receipt. In this packet the answer is `no` for every row; part 2 does not change that, because no pre-cut candidate exists yet.

**Disposition vocabulary:**

- **keep** — the test proves its contract row; leave it alone.
- **strengthen** — the behaviour is real and the test is pointed at it, but the assertion does not prove it. Never a deletion: a weak assertion on a critical behaviour is always strengthened.
- **consolidate** — several tests cover the same ground and one of them is the honest one; fold the others into it.
- **move** — the proof exists at the wrong layer (a unit seam standing in for a protocol round-trip, or vice versa).
- **remove** — the test asserts nothing about the product. Used once in this packet, on the operator's explicit 2026-09-04 ruling (a).
- **not yet reviewed** — inside scope but not read in this packet. Listed again under Coverage limits.

## Three facts that bound almost every row below

These were established from source, and they change how much most protocol tests prove. They are stated once here and referenced by rows rather than repeated.

**(F1) The integration fixture runs with authentication disabled by default.**
`tests/dotnet/Honua.TestKit/Mixins/WebAppFixturePostgresWiringMixin.cs::ApplyCommonHostSettings` sets `HONUA_DEV_AUTH=true` and `HONUA_DEV_AUTH_ALLOW_BYPASS=true` on **every** `WebAppFixture` host, shared and isolated alike (`WebAppFixtureSharedBootstrapMixin.cs` repeats it for the shared factory). In `src/Honua.Hosting/Features/Authentication/ApiKeyAuthenticationHandler.cs`, `HandleAuthenticateAsync` short-circuits on that bypass and returns a successful `"dev-bypass"` principal **before any credential is read**. A fixture opts back into real authentication by calling `ConfigureWebHost(b => b.UseSetting("HONUA_DEV_AUTH", "false"))`, which runs after `ApplyCommonHostSettings` and wins.

The numbers: 467 test files use `WebAppFixture`; **134 sites opt out**. Across the four protocol test projects, 198 files use the fixture and **16 opt out** — none of them in `Honua.Protocols.GeoServices.Tests` or `Honua.Protocols.OgcClassic.Tests`, which contain no opt-out at all. Consequence: the large majority of protocol tests prove **functional behaviour only** and prove nothing about authorization, and a test on a non-opted-out fixture whose name says "Anonymous" is describing a client that is in fact authenticated. Rows below name the fixture so the distinction is never guessed.

**(F2) The fixture that does prove authorization does not touch the database.**
`tests/dotnet/Honua.TestKit/Helpers/ServiceRbacTestFixture.cs` sets `HONUA_DEV_AUTH=false` and installs a header-driven `TestAuthHandler`, so its decisions are real. But it builds on `TestWebApplicationFactory`, which replaces `IFeatureReader`/`IFeatureWriter`/`ITileProvider`/`IStreamingFeatureStore` with the in-memory `tests/dotnet/Honua.TestKit/Infrastructure/TestFeatureStore.cs`. Consequence: authorization is proven at the endpoint/middleware layer against a fake store. No test proves that a denied principal is refused **records that actually exist in PostGIS**.

**(F3) The required per-PR check does not run the integration suite.**
`.github/workflows/pr-gate.yml` runs the lean gate, which executes `--filter "Tier=Fast"` on `Honua.Server.Tests`, the architecture tests, and two named MCP tests, plus a boot/migrations smoke. Everything below marked `api-integration` runs in the trailing full matrix, not on the required check. That is the adopted eventual-quality landing model and is not itself a defect — but it means "the gate is green" never implies any row below is proven.

## Priority 3 — Geospatial correctness and the four GA cloud-native formats

Cloud-native format serving — COG, Zarr, GeoParquet, PMTiles — is GA by the 2026-09-04 decision 3, which also makes every finding of the cloud-native hunt on those surfaces first-release-gate must-pass. The rows below are about **evidence**, not those defects.

One fact frames the whole section: **`docs/cng-status.md` (lines 70-76) states that Honua does not author COG and only reads/transcodes Zarr.** Any GA row that reads as "Honua produces a COG" is a claim the product does not make. The GA claim is *serving from* and *reading* these formats.

## Good patterns to preserve

Strengthening work below means "look like these". None of them may be weakened or deleted.

1. **Authorization with a zero-side-effect assertion** — `tests/dotnet/Honua.Server.Tests/Import/ImportAuthorizationParityTests.cs::ImportAuthority_RealTransportTenCaseMatrix_MatchesRestAdminWriteContract`. Two surfaces (REST and MCP) × five principal profiles over real HTTP; every denial asserts `_effects.Should().BeEmpty(...)` and `DidNotReceive().ImportFileAsync(...)` alongside the status. This is the shape every denial row in this map is asking for.
2. **Per-operation RBAC as a cross-protocol matrix** — `CrossProtocolPermissionMatrixTests.cs`. A theory over 7 edit-kind combinations × grant-present/absent × FeatureServer and gRPC, plus OData, OGC API Features and OGC API Tiles, with both the grant-honoured and the fall-back-to-coarse-deny direction asserted.
3. **Mutate, read back, then prove the invalid mutation changed nothing** — `FeatureServerMutationScenarioTests` and `OgcFeaturesMutationScenarioTests`, in both halves.
4. **Filtering asserted by exact ids** — `OgcFeaturesEnhancementsTests::GetItems_WithDateTimeParameter_FiltersFeatures` (`ids.Should().Equal(1, 2, 4)`), `ODataFilterMatrixTests`, `ODataBboxShorthandTests` (`Contain`/`NotContain` by named id).
5. **A decoded-output oracle against a real tool** — `VectorReproject_WithRealOgr2Ogr_AppliesNad27ToWgs84DatumShift`, whose two-sided bound catches both an identity-transform bug and a wrong-CRS bug.
6. **Byte-exact decode against an independent implementation** — `TileDecompressorFixtureTests` (10 GDAL-produced COG fixtures, byte-compared against GDAL's own decode, no skip conditions).
7. **Fail-closed coverage derived from the product** — `EntitlementProbeRegistry` builds its probe list from `FeatureCatalog` itself, so a new gated key with an HTTP surface and no probe fails the build, and `KnownGaps` is empty.
8. **Fault injection at every commit boundary** — `AlertEvaluationAtomicityTests::CommitEvaluationAsync_FailureAtEveryBoundary_ReplayCommitsOneTransition`: a throw at each boundary, nothing partially committed, replay idempotent, exactly one transition.
9. **Counts-based anti-skip tripwire in CI** — `ci.yml:1478-1535` fails when any `[GdalCliFact]` case is skipped or when none passed. This is how "skipped required cells are non-passing evidence" is enforced in practice, and it should be copied to the container and PDAL lanes.

## Weak-assertion patterns found, as a checklist

Recorded so part 2 and the burn-down can grep for them rather than rediscover them.

- Accepting refusal alongside success — `BeOneOf(OK, Unauthorized)`, `BeOneOf(OK, Accepted, Unauthorized)`.
- Accepting a server error as a pass — `BeOneOf(Created, ServiceUnavailable, InternalServerError)`.
- `NotBe(Forbidden)` / `NotBe(Unauthorized)` / `NotBe(NotFound)` in place of an exact status.
- Shape-only — "the response has a `features` array", `NotBeEmpty()`, magic bytes (`PAR1`, PNG signature, `II`/`MM`).
- Denial asserted by status alone, with no state or disclosure check.
- Echo-only mutation assertions with no read-back.
- Filtering asserted by a per-row re-check of the same predicate, proving no false positives but never no false negatives.
- Vacuous pass — a `foreach` with no non-empty precondition, or an early `return` on an empty fixture.
- Assertions on a method the production code cannot call (`DidNotReceive().SetAsync` where only `TrySetAsync` exists).
- A test name that promises behaviour the body never exercises (`…SupportsAtomicity` with no failing member; `…RecoversAcrossRestart` with no restart; `…ConcurrentOperations…` with disjoint keys; `…ReconcilesAgainstSource` with a magic-byte check).
- Sequential awaits standing in for concurrency.
- Fixtures that make the assertion circular — a fake runner that writes the test's own bytes; a fake store that returns hardcoded content when nothing was written; a hand-authored tool stdout parsed back as if measured.
- Silent skips — `pytest.skip` on a 404/501, `Skip` when a binary is absent, `describe.skip` when an env var is unset, `[RequiredEnvironmentFact]` with no counts tripwire.
- `[Endpoint]`/`[Operation]` annotations on tests that never issue a request (all 15 in `FileUploadSecurityTests.cs`).

## Coverage limits

This is a manual review of representative areas. It is not a claim that every test was audited, and the disposition column says which rows were read and which were not.

**Method and its limits.** Every row above was produced by reading test bodies, fixtures and the code under test. Where a row says "none found", the greps that were run are named in the linked issue. Three method limits are worth stating plainly:

- Coverage was assessed by reading, not by executing. No test was run and no coverage tool was used, so a test that is currently failing, quarantined or excluded by a trait filter may be cited above as if it passes. `[FlakyTest]` and `[RequiredEnvironmentFact]` tags are called out where found, but not exhaustively.
- `[Endpoint]` and `[Operation]` annotations were treated as untrustworthy, on evidence: all 15 tests in `FileUploadSecurityTests.cs` tag `POST …/addAttachment` while calling only static validators. Any coverage table derived from those attributes will over-credit. The API-surface inventory guard is an inventory, not proof.
- No candidate-bound receipt exists for any row, because no pre-cut candidate exists. Every "no" in the receipt column is the same "no".

**Named areas inside the packet's scope that were NOT reviewed:**
