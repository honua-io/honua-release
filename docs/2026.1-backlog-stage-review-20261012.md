## Phase boundary

| Phase label | Meaning |
|---|---|
| `stage/rc` | Existing RC implementation, integration or required producer/gate work. An open tracking issue is not necessarily outstanding server code. |
| `stage/ga` | Post-cut work and qualification against the actual lock. Existing scope rulings determine which work blocks GA. |
| `stage/2026.1.x` | Explicitly deferred patch work, including lineage and the signed update feed; not silently moved to 2026.2. |
| `stage/2026.2` | Optional improvements and development architecture changes outside the RC contract. Bounded repairs of required gates remain required. |
| `stage/internal` | Delivery/fleet tooling; does not expand the customer release contract. Existing operational owners retain their work. |
| `stage/admission-review` | Verify whether the finding remains unfixed and identify its supported workflow, security/integrity floor or required gate before RC admission. This is not an accepted limitation or permission to ignore a failing gate. |

These labels supplement the existing four `bucket/*` labels. They do not change automated mint/promotion criteria, supported targets, private security dispositions or the required client-test denominator. The existing decision record is a dated gate-policy snapshot; this current intake report is not a new GO decision.

The canonical [release plan](https://github.com/honua-io/honua-release/issues/376) owns the RC and GA exit criteria and current execution sequence; this document records the backlog review, not a second release plan.
