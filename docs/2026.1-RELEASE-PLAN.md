hand-edited.

## Milestones

Targets count from adoption on 2026-09-29; the canonical plan owns changes to these dates.

| Milestone | Target | Bar |
|---|---|---|
| M1: developer preview and first blog post | by 2026-10-13 | Recorded genuine-model dogfood run on real AWS: install → publish a layer and 2D map → roll back → tear down; reviewed claims, teardown deny and least-privilege role. The install manifest stays `pre-cut-rehearsal`. |
| M2: first certified lock `2026.1-rc.3` | 2026-10-27 to 2026-11-03 | First all-green nightly strict train on trunk head mints a signed lock; genuine-model journey passes on all four GA cells against a certified lock. Nightlies use the deterministic driver on all four cells plus one genuine-model cell (ECS, Redis off). |
| M3: GA `honua-2026.1.0` | 2026-11-17 to 2026-12-01 | Select promotion candidate rc.N; gather genuine-model evidence on all four cells, signed rc.3 → rc.N → rc.3 update/rollback proof, Esri and CITE bound to the lock; burn 48 hours with seven lock-bound canaries while trunk moves; pass GA docs gates and move channels through promotion. |

If M2 is not met by 2026-11-03, the operator rules on scope before work continues; dates do not slide
silently. R18–R21 establish continuous certification: no freeze or hand re-pin. New commits and newer
locks do not reset a selected lock's burn; a failure of that lock ends it. Promotion is allowed from
hour 48 until any evidence passes its freshness bound, without a 72-hour deadline or later strict-train
requirement. Every consumed evidence class is declared nightly or qualifying and bound to the lock.

GA cells are {All-ECS, Lambda + Batch} × {Redis off, Redis on}. Mixed ECS + Batch and EKS run as
informational Preview cells. Each required journey cell passes within two recorded attempts, with
failures attributed to model or infrastructure. See [BURN-IN-PROMOTION.md](BURN-IN-PROMOTION.md) for the
readiness contract and remaining workflow integration.
