# Add Console to a Compose quickstart install

The customer quickstart package (`compose.yaml`, `compose.executor.yaml`, `quickstart.py`) installs Honua Server
without Honua Console. Use this page to add Console, and Studio inside it, to an install you already have. It
assumes the 2026.1 package layout: secrets live in files under `secrets/`, and `.env` names the package's compose
files in `COMPOSE_FILE`.

Studio in Console does not enable model calls. No AI provider, credential or invocation ledger is needed.

## 1. Check the server setting

The package's `honua` service sets `Studio__EndUserAuthorization__Enabled: "true"` (honua-server #6896). Studio
customers keep resource authorization, draft ownership and separate publication approval. If your `compose.yaml`
predates it, take the 2026.1 package rather than editing the server.

## 2. Configure your identity provider on Server

Console users sign in through your identity provider. Point Server at it with these settings, in an override file
for the `honua` service (for example `identity.yaml`), never by editing `compose.yaml`:

```yaml
services:
  honua:
    environment:
      Oidc__Enabled: "true"
      Oidc__Generic__Enabled: "true"
      Oidc__Generic__Authority: "https://login.example.com/your-tenant"   # your issuer
      Oidc__Generic__ClientId: "honua"                                     # your client id
```

Apply it with the package's own compose files, as in step 4 (`identity.yaml` in place of `console.yaml`, and the
service `honua`).

## 3. Write the Console override

Save this as `console.yaml` beside `compose.yaml`. Take the image digest from the 2026.1 release lock (the
`console` entry); never use a tag.

<!-- docs-validation:console.override -->
```yaml
services:
  console:
    image: ghcr.io/honua-io/honua-console@sha256:<digest from the release lock>
    # Console reads the administrator key from the package's secret file, as the server does.
    entrypoint:
      - bash
      - +x
      - -euc
      - |
        { set +x; } 2>/dev/null
        key=$$(< /run/secrets/honua_admin_password)
        [ -n "$$key" ] || { echo "empty administrator secret" >&2; exit 1; }
        export HONUA_ADMIN_API_KEY="$$key" Honua__Server__AdminApiKey="$$key"
        unset key
        exec "$$@"
      - load-secrets
    command: ["dotnet", "Honua.Console.Web.dll"]
    secrets:
      - honua_admin_password
    environment:
      ASPNETCORE_URLS: "http://+:8080"
      HONUA_SERVER_BASE_URL: "http://honua:8080"
      Honua__Server__BaseUrl: "http://honua:8080"
      Studio__EmbedJsStudio: "true"
    ports:
      - "127.0.0.1:${HONUA_CONSOLE_PORT:-5174}:8080"
    healthcheck:
      test: ["CMD-SHELL", "test -s /app/wwwroot/version.json"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 30s
    restart: unless-stopped
    read_only: true
    cap_drop: ["ALL"]
    security_opt: ["no-new-privileges:true"]
    tmpfs: ["/tmp:noexec,nosuid,size=100m"]
```

## 4. Start Console

Run this in the install directory. It keeps the package's own compose files (`COMPOSE_FILE` in `.env`) and adds
`console.yaml`. Do not pass `-f` files: a `-f` list replaces `COMPOSE_FILE`, drops the executor and image
overrides, and makes Compose recreate the server.

<!-- docs-validation:console.start -->
```bash
files="$(sed -n 's/^COMPOSE_FILE=//p' .env | tail -n 1)"
COMPOSE_FILE="${files:-compose.yaml}:console.yaml" docker compose up -d --no-deps --wait console
```

`--no-deps` starts only Console. The server keeps running unchanged.

## 5. Open Studio

Open `http://localhost:5174` (or your `HONUA_CONSOLE_PORT`), sign in through your identity provider and open Studio
to author maps, save and reopen versions, and request publication.

## Remove Console

```bash
files="$(sed -n 's/^COMPOSE_FILE=//p' .env | tail -n 1)"
COMPOSE_FILE="${files:-compose.yaml}:console.yaml" docker compose rm -s -f console
```
