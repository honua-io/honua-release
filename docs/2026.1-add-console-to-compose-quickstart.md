# Add Console to a Compose quickstart install

> **2026.1 rc.2:** Compose is the local evaluation path, not a certified production target.
> The primary GA production deployment is the AWS CloudFormation Launch Stack on ECS Fargate
> (single-node default, zero Redis) with RDS PostGIS and Console deployed as a version-locked
> static SPA in S3 behind CloudFront at `/console/` (or `ConsoleBundleVersion=off` when
> connecting to a central Multi-Environment Console Hub).

Honua Console ships as a **static Blazor WebAssembly SPA** (`honua-console-<version>.zip`)
mounted under `/console/`. There is **no Console Docker container** in 2026.1-rc.2; Console
container publication was retired in favor of the static bundle.

The customer quickstart package (`compose.yaml`, `compose.executor.yaml`, `quickstart.py`)
installs Honua Server without Honua Console. Use this page to serve the static Console bundle
against a local Compose quickstart install. It assumes the 2026.1 package layout: secrets live
in files under `secrets/` (honua-server #6888), and `.env` names the package's compose files
in `COMPOSE_FILE`.

Studio in Console does not enable model calls. No AI provider, credential or invocation ledger
is needed.

## 1. Configure sign-in on Honua Server

OIDC is the primary operator sign-in method for production deployments (Amazon Cognito by
default on AWS Launch Stack, or an external OIDC provider such as Keycloak, Microsoft Entra ID
or Okta). For local Compose evaluation, you can configure an OIDC provider or sign in with the
local `admin` password configured in `secrets/honua_admin_password`.

To configure an OIDC provider, put these settings in an override file for the `honua` service
(for example `identity.yaml`), never by editing `compose.yaml`:

<!-- docs-validation:identity.override -->
```yaml
services:
  honua:
    environment:
      Oidc__Enabled: "true"
      Oidc__Generic__Enabled: "true"
      Oidc__Generic__Authority: "https://login.example.com/your-tenant"   # your issuer
      Oidc__Generic__ClientId: "honua"                                     # your client id
```

Apply it with the package's own compose files (the `honua` service is recreated with the new settings):

```bash
files="$(sed -n 's/^COMPOSE_FILE=//p' .env | tail -n 1)"
COMPOSE_FILE="${files:-compose.yaml}:identity.yaml" docker compose up -d --no-deps --wait honua
```

## 2. Enable end-user Studio (optional)

As shipped, Studio is for administrators: the package leaves
`Studio__EndUserAuthorization__Enabled` off. To let your organisation's other users work in
Studio, add this line to the same `identity.yaml` and apply it again as in step 1. This lets
non-admin principals, including non-admin API keys, create and manage their own Studio drafts;
publication still needs approval.

<!-- docs-validation:end-user-studio.override -->
```yaml
services:
  honua:
    environment:
      Studio__EndUserAuthorization__Enabled: "true"
```

## 3. Download and extract the static Console bundle

Obtain the version-locked `honua-console-<version>.zip` archive and its companion `.zip.json`
receipt from the 2026.1 release assets (or build them from `honua-console` following the
[Build artifact contract](https://github.com/honua-io/honua-console/blob/trunk/docs/deployment/BUILD_ARTIFACT.md)).
Verify the ZIP SHA-256 digest against the receipt before extracting it beneath `/console/`:

```bash
mkdir -p console-static/console
unzip -q honua-console-<version>.zip -d console-static/console
```

Configure `console-static/console/config.json` with public deployment settings only — never
put an admin password, API key, client secret or operator token in `config.json`:

```json
{
  "apiBaseUrl": "/",
  "managementApiBaseUrl": null,
  "auth": { "mode": "builtin", "authority": null, "clientId": null, "scopes": [] },
  "v4Enabled": true
}
```

Set `"auth": { "mode": "oidc", ... }` when using same-origin server-brokered OIDC. Keep the
license files (`LICENSE`, `NOTICE`, `licenses/`) beside the extracted bundle.

## 4. Serve Console on the same origin as Honua Server

Place a local reverse proxy (for example Caddy or nginx) in front of the static directory and
the local Honua Server (`http://127.0.0.1:8080`):

- Route `/console/*` to `console-static/console/` with SPA fallback to `/console/index.html`
  for extensionless routes (do not rewrite missing assets or API errors to HTML).
- Route API and authentication paths (`/api/*`, `/admin/*`, `/rest/*`, `/ogc/*`, `/healthz/*`)
  to `http://127.0.0.1:8080`.
- Apply the caching and Content-Security-Policy headers documented in
  [Deploy the static Console bundle](https://github.com/honua-io/honua-console/blob/trunk/docs/deployment/STATIC_SPA.md).

For local asset and navigation testing without a reverse proxy, see
[Run Console locally and in staging](https://github.com/honua-io/honua-console/blob/trunk/docs/deployment/LOCAL_AND_STAGING.md).

## 5. Open Console and Studio

Open `http://<your-proxy-host>/console/`, sign in through your identity provider (or with the
local `admin` password on a local evaluation install), and open Studio to author maps, save
and reopen versions, and request publication.

Opt-in preview features such as Geofence Alerts (`alerts.geofence`) are off by default in
2026.1-rc.2 and display a Preview status unless explicitly enabled on Honua Server.
Geoprocessing services (`GPServer` / OGC API - Processes) expose executable processes and tasks
rather than feature layers.

## Remove Console

Stop your static server or reverse proxy and remove the extracted `console-static/` directory.
The Compose `honua` server stack continues running unchanged.

## Legacy Compose harness fixture (AI-arc test runner only)

> **Deprecated for 2026.1-rc.2 customer deployments.** Console container publication has been
> retired in favor of the static Blazor WebAssembly bundle above. The blocks below are retained
> solely for the existing `tools/ai_arc_local.py` Compose test harness until it migrates to
> static bundles.

<!-- docs-validation:console.override -->
```yaml
services:
  console:
    image: ghcr.io/honua-io/honua-console@sha256:<digest from the release lock>
    # Console reads the administrator key from the package's secret file, as the server does.
    entrypoint:
      - bash
      - +x
      - -euc
      - |
        { set +x; } 2>/dev/null
        key=$$(< /run/secrets/honua_admin_password)
        [ -n "$$key" ] || { echo "empty administrator secret" >&2; exit 1; }
        export HONUA_ADMIN_API_KEY="$$key" Honua__Server__AdminApiKey="$$key"
        unset key
        exec "$$@"
      - load-secrets
    command: ["dotnet", "Honua.Console.Web.dll"]
    secrets:
      - honua_admin_password
    environment:
      ASPNETCORE_URLS: "http://+:8080"
      HONUA_SERVER_BASE_URL: "http://honua:8080"
      Honua__Server__BaseUrl: "http://honua:8080"
      Studio__EmbedJsStudio: "true"
    ports:
      - "127.0.0.1:${HONUA_CONSOLE_PORT:-5174}:8080"
    healthcheck:
      test: ["CMD-SHELL", "test -s /app/version.json || test -s /app/wwwroot/version.json"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 30s
    restart: unless-stopped
    read_only: true
    cap_drop: ["ALL"]
    security_opt: ["no-new-privileges:true"]
    tmpfs: ["/tmp:noexec,nosuid,size=100m"]
```

<!-- docs-validation:console.start -->
```bash
files="$(sed -n 's/^COMPOSE_FILE=//p' .env | tail -n 1)"
COMPOSE_FILE="${files:-compose.yaml}:console.yaml" docker compose up -d --no-deps --wait console
```
