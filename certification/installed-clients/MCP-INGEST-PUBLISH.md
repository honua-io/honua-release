# Canonical ingest and published-service readback producer

This release-owned producer implements three coupled operation adapters:
`ingest_dataset`, `publish_service` and `resources/read:Published service`.
The downstream repository must verify one protected immutable source set before
import or execution, including both new Python files, this JavaScript module,
the shared map/wire/fixed-launch dependencies, render oracle and authored fixture.
No callback-provided transport or client identity can replace the fixed installed
SDK runner or public Inspector CLI. The trusted workflow/source/artifact boundary
attributes execution; retained JSON is not process or database attestation.

The fixture comes from the independently authored `sites.features` records in
`fixture.v1.json`. The journey sends their complete GeoJSON through inline ingest,
uses the returned connection/schema/table/geometry/primary-key tuple for publication,
and retains every intermediate original client/wire result. A missing catalog
connection hint fails without substituting the bootstrap connection. Registration
must use supported product fields; caller hints do not establish semantic database
identity.

Publication's returned `layerId` identifies physical storage. The database observer
binds it to `storageLayerId`, preserving the separate public publication index.
The actual fresh published-service resource exposes that public index; the next
fresh canonical `query_features` invocation uses it and the exact returned service
name. The pure oracle independently cross-checks both identities with one committed
PostGIS graph/data snapshot. Synthetic controls deliberately use storage741 and
public0 so accidental ID equality cannot pass.

The first execution path requires `Completed`. `Queued` and `RequiresApproval`
remain explicit nonpass with raw observations; asynchronous publication is not
exercised or credited. The larger issue remains open until that supported journey
also has its proper terminal-status/readback proof. No pending publication is
retried as a new mutation to conceal a broken acknowledgement.

Only an explicitly owned disposable candidate may be restarted. Safe Docker
readback binds its full container ID, exact image digest and source before restart;
restart must advance its actual start timestamp while keeping those identities.
Readiness is bounded. Independent persisted snapshots and fresh resource/query
sessions before and after restart must retain all authored typed attributes,
allocated feature IDs, exact geometry/SRID and publication binding. No extra
promotion record is seeded to make the returned URI resolve. Objects stay in the
owned disposable database until maintained workflow teardown; no per-object cleanup
or hidden-side-effect exclusion is inferred from response shape.

Typed invalid-ingest/publish probes, unknown resource and genuine anonymous
invocation/resource refusals are required. Each uses a distinct newly initialized
session and no inherited API key/Authorization/Cookie. Inspector local discovery
refusal without an invocation remains unqualified. The controlled offline suite
and helper rejudge/source-binding tests do not prove any actual server, installed
client or current release candidate passed. All82 rows, auth/cohort and global
behavior/cancellation/pagination requirements remain intact.

Refs honua-release699 (full scoped execution and queued path remain),
honua-server6379 (product publication readback and tenant reconciliation),
honua-release695 (auth/cohort adoption), honua-release181 (frozen cohort convergence),
and honua-release652 (full augmentation and exact-candidate qualification).


Inspector anonymous ingest/publication selects the supported public `setup` view
through actual CLI metadata. The selected historical server source3ecd includes
both operations in setup.v3; discovery grants no invocation authority. Original
tools/list request/response bytes, pagination, same fresh session and absent
credentials must advertise the target exactly once before its real tools/call.
Missing/unsupported views and local discovery refusal remain nonpass. The producer
never substitutes a catalog or borrows the authenticated full export for anonymous
invocation. Existing map-package anonymous discovery behavior is unchanged.

Retained real run39221223302 showed that the historical server's authenticated
full catalog continues after eight 12-tool pages. Inspector must finish its own
catalog traversal before invoking a tool. The observer therefore retains at most
32 pages, with the existing 2MiB per-response and 8MiB total byte limits unchanged.
The pure judge requires a complete cursor chain, distinct request IDs, no repeated
cursor, the same session/credential/view and exactly one advertised target. A
33rd page, an unfinished chain or a discovery refusal earns no invocation credit.
Offline forwarding and oracle controls are not installed-client qualification.


Missing-table publication is checked as its own typed Failed operation handle
inside a successful MCP tool-result envelope. Its reason must identify the actual
missing source table, its handle must be distinct from the completed operation,
and it must carry no created layer/service/revision, proposal, approval or job
identity. A transport-success/CLI0 outcome cannot make Failed mean Completed.
Short owned import names must retain their actual imported_ table identity.

Connection names are valid caller selectors; they are not registry GUIDs.
The positive persisted-binding control uses an actual GUID. A named selector with
no independently resolved canonical/default-catalog binding remains explicitly
unproved; the producer does not substitute the bootstrap connection ID or call
that missing observer proof a runtime regression. Actual returned selectors and
partial results remain retained. Independent alias/default-catalog provenance,
queued publication and exact-candidate qualification remain open under issue699.
