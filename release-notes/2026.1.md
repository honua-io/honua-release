# Honua 2026.1

> **Status: Release Candidate.** This is the 2026.1 Release Candidate. General availability follows
> FOSS4G North America (November 2-4, 2026). Use the RC to evaluate and to run pilots. The GA
> release record will state which qualification evidence was collected against which candidate;
> until then, the GA tier below describes the commitment, not a completed qualification.

Honua is a geospatial platform built for AI agents and people to use together: the server, SDKs
for JavaScript, Python and .NET, an MCP server for agents, and Honua Studio for AI-assisted map
making.

Honua 2026.1 is the first release of Honua Server, the server-side platform for teams that run
their own GIS infrastructure and want AI agents and people to work on it through the same
vocabulary. It replaces the proprietary or GeoServer-based serving tier organisations run today
with one server that speaks the protocols their clients already use.

Honua Server is Fair Source. The source is published under the Fair Core License, Version 1.0,
ALv2 Future License (FCL-1.0-ALv2): run it yourself, including on air-gapped infrastructure, read
it, modify it, and redistribute it for any purpose except offering a competing product. Each
release becomes Apache-2.0 two years after it is published. The SDKs, Console, Studio and the open
protocol projects are Apache-2.0 today.

This document is the human description of the release. The sections that follow it are generated
from the certified platform manifest and are the authoritative record of what was pinned, which
gates passed, and how to upgrade.

## Editions and licensing

2026.1 ships with licensing **disabled** (`Licensing__Mode=Disabled`), and that is the documented
deployment posture for every target, including Production. No license file, signing key or edition
selection is required, every catalog entitlement is active, and no serving-unit metering or band is
measured or enforced. Authentication, authorization, resource limits and capability maturity
still apply. The Community, Pro and Enterprise editions, signed license
envelopes and capacity metering are implemented and will be hardened and enabled in 2026.2.

| Edition (when licensing is enabled) | Adds |
|---|---|
| Community | The documented Community protocol surfaces, publishing, one-shot file import, portal tokens |
| Pro | GeoServices editing, spatial analytics, real-time streams, Redis caching, geocoding, single-provider OIDC, routing (NAServer), core branch versioning (Preview) |
| Enterprise | Multi-provider OIDC governance, claim-to-role mapping, organisational approval and policy controls, specialised scene ingest and I3S (Experimental) |

See [Editions and licensing](https://github.com/honua-io/honua-server/blob/trunk/docs/concepts/editions-and-licensing.md)

## Known limitations

- **x86_64 only.** The ARM64 children of multi-architecture images are not qualified for 2026.1.
- **Single-tenant only.** Each deployment serves one tenant.
- **The .NET SDK has no OGC API Tiles client.** `Honua.Sdk` 1.12.0 does not wrap the OGC API
  Tiles endpoints ([honua-sdk-dotnet#405](https://github.com/honua-io/honua-sdk-dotnet/issues/405));
  the two .NET certification cells that depend on it are declared blocked for 2026.1 and targeted
  at 2026.1.x. The server's Tiles endpoints are unaffected; .NET applications can call them over
  HTTP.
- **Client packages ship without publisher attestations.** The server images (the candidate image
  and the AWS Lambda image) carry signed SBOM and build-provenance attestations. The client
  packages pinned for 2026.1 were published before their attestation workflows existed and cannot
  be attested retroactively: `@honua/sdk-js` 0.2.10 and its cohort (`@honua/sdk`,
  `@honua/sdk-esri-compat`, `@honua/react`, `@honua/geometry`, `@honua/app-platform`,
  `@honua/mcp-server` 0.2.10, `create-honua-app` 0.2.3), `honua-sdk` 0.1.19 and `honua-admin` 0.1.12,
  `Honua.Sdk` 1.12.0, `Geospatial.Grpc` 1.0.3, the geospatial-mcp schema index at `d5a09d13`, and the
  honua-iac `v0.3.0` source archive. Each is accepted only at its exact pinned digest under the
  dated founder ruling `sdk-attestation-exception-2026-10-27`
  ([honua-release#1004](https://github.com/honua-io/honua-release/issues/1004)), and each exception
  ends with that component's first attested release, targeted at 2026.1.1. The registries' own
  integrity hashes still apply.
- **Imported attributes are stored as JSON.** Dataset import stores each source feature's
  attributes in one JSON `properties` column next to its geometry, and query responses return
  `properties` as a JSON object. Flattening attributes into typed columns is planned for 2026.1.x
  ([honua-server#6640](https://github.com/honua-io/honua-server/issues/6640)).
- **FeatureServer replication is MVP-scoped.** Create, extract, synchronize and unregister work, but
  the first sync returns the full add set and later syncs have no database-level incremental change
  tracking. Use it for short-lived sync, not as an offline geodatabase replacement.
- **64-bit integer fields need client support.** Fields are advertised as `esriFieldTypeBigInteger`;
  the stock QGIS 3.40 GeoServices REST provider does not recognise them.
- **WMTS serves WebMercatorQuad only** on the MapServer alias and the classic OGC surface.
- **Image export needs Redis on cloud-backed storage.** MapServer and ImageServer image exports that
  spill to cloud-backed temporary storage require a Redis connection for quota coordination; without
  it the request is refused with a capacity error. OGC API Maps rendering does not use that path.
- **H3 analytics need the `h3` PostgreSQL extension** in the database; providers without it return
  "not supported" for H3 operations. Density and the other analytics do not depend on it.
- **The Oracle provider is bundled** in the default image in 2026.1 and carries Oracle's client
  license terms; it is scheduled to become an optional package.
- The full list, stated as fact with evidence links, is in
  [Supported clients and known limitations](https://github.com/honua-io/honua-server/blob/trunk/docs/reference/compatibility/clients.md)
  and the per-protocol [GeoServices parity](https://github.com/honua-io/honua-server/blob/trunk/docs/reference/compatibility/geoservices-parity.md) page.

## Known issues in the Release Candidate

- **demo.honua.io runs without Redis.** Redis was disconnected from the public demo on
  2026-10-24 after a defect in Redis-connected serving on AWS Lambda
  ([honua-server#6558](https://github.com/honua-io/honua-server/issues/6558); fix in review as
  [honua-server#6644](https://github.com/honua-io/honua-server/pull/6644)). Until Redis is
  reconnected, MapServer and ImageServer image exports on the demo answer with a capacity error,
  and features that need a Redis job store are refused with a typed error rather than run.
- **Preview surfaces** (Helm, AWS Lambda, the GP catalog and Studio) are in the RC but do not
  gate it. Report problems with them as issues; they may change before GA.
- **Two .NET certification cells are declared blocked:** OGC API Tiles through `Honua.Sdk` (no
  client, above) and published-SDK service-layer import fidelity, which has no evidence producer
  yet. Both are targeted at 2026.1.x.

## Upgrade notes

**Breaking change: credential and identity management needs full-administrator authority.**
API keys granted only `admin:write` or `admin:manage` now receive `403` on these Admin API routes:

- `POST /api/v1/admin/api-keys`, `POST /api/v1/admin/api-keys/{id}/rotate` and
  `POST /api/v1/admin/api-keys/{id}/revoke`
- `PUT /api/v1/admin/users/{id}/roles` and `DELETE /api/v1/admin/users/{id}`
- `POST /api/v1/admin/oauth-clients` and `DELETE /api/v1/admin/oauth-clients/{id}`

Request and response shapes are unchanged, and scoped keys keep read access to these resources and
admin write access elsewhere. Move automation that manages keys, users or OAuth clients to a
full-administrator credential (a key granted `admin`, `*` or `admin:*`, the bootstrap credential, a
client certificate or an administrator session) or to an approved operation before you upgrade.
This change is part of the security hardening in this release; advisories that apply to earlier
builds are published together with the release.

**From nightly images or earlier pre-release snapshots.** These are engineering builds, not
releases, and carry no upgrade guarantee. Take a database backup first, follow the
[upgrade runbook](https://github.com/honua-io/honua-release/blob/trunk/docs/UPGRADE-RUNBOOK.md),
and plan to restore that backup if the upgrade fails.

**From this RC to GA.** Updating from one certified candidate to the next and rolling back again on
AWS is part of GA qualification. The GA release notes will state the result and any step the RC
needs before it moves to GA.

## Rollback

2026.1 is the first release, so there is no earlier release to roll back to. Note the rule it sets
for later releases: a pre-release image is **not** a safe rollback target across any migration. The only safe
way back from a later release to 2026.1 is restoring the backup taken before the upgrade, and the
server refuses to start when the database schema is ahead of the binary. The customer procedure is
the [upgrade runbook](https://github.com/honua-io/honua-release/blob/trunk/docs/UPGRADE-RUNBOOK.md).
