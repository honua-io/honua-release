# 2026.1 AI delivery arc

Decision D9.3 makes the supported administration boundary explicit. The complete
control plane is the Admin API, its operation catalog and executors, `honua admin`,
and the policy-governed `honua_admin_*` MCP family. Console still ships, but as the
focused human client for inspection, approval, operations, audit, diagnostics,
health/release state, and recovery—not as a full administration-parity gate.

The release journey is one candidate-bound sequence, executed on both the local
Docker candidate and the AWS ECS candidate:

1. Install the immutable candidate in local Docker; separately provision that
   same candidate on AWS ECS and retain its apply/readiness/admin-MCP handoff receipt.
2. Configure connections, imports, services, layers, access, and keys through the
   governed admin API/MCP surface.
3. Discover and execute Buffer through the AI-facing Esri GP tools and the Honua
   GPServer compatibility path, then run the native dataset-reference Buffer verb.
4. Compose the map, app, and dashboard as three distinct Studio families; save
   each as an immutable version, read that exact version, and reopen it as a new draft,
   including the published layer, retained GP artifact, style, view,
   TOC/chart/control, and interaction.
5. Propose publication without bypassing human confirmation.
6. Inspect the same connection, layer, GP job, draft, proposal, candidate, and audit
   identifiers in Console, then approve or reject through the focused client.
7. Verify the stable approved URL and retain the candidate, audit, and release receipts.

The deterministic contract driver is owned and shipped by `honua-sdk-js`; this repo
consumes it from the exact SDK SHA in `platform-manifest.yaml`. The release receipt
binds Console's `candidateId` to the manifest SHA-256 and `releaseId` to
`platformRelease`, so evidence from another candidate cannot be joined accidentally.
The ECS provisioning receipt is not sufficient by itself: a separate ECS
delivery-arc receipt must prove every downstream stage and the public HTTP 200.
External receipts declare their target and named passed checks; the release gate
rejects evidence-light `passed` rows.

Local and AWS evidence are now independent producers in the release train. The
local producer never waits for or consumes an AWS receipt, and the ECS producer
does not depend on the local producer. A final `always()` aggregate downloads
only the exact named artifacts from its own train run after both producers have
finished. It also joins the AWS model receipt to the validated provision-binding
bytes, provisioned endpoint hash, and exact governed Actions run, preventing
same-candidate evidence from separate deployments from being mixed.
The local producer starts a digest-pinned ephemeral HTTPS tunnel, verifies the
running tunnel image, host-network target, local readiness, and public readiness
before any journey receipt can pass, then removes the tunnel during teardown.

The current manifest truth is intentionally partial. The pinned server owns a real
396-operation Admin OpenAPI schema, so that count is recorded. The 119-tool operation
catalog/MCP family, the SDK journey bundle, Studio container, focused Console receipt,
real-model map/app/dashboard save/reopen receipt, AWS ECS provision receipt, and full
AWS ECS delivery-arc receipt must land and be re-pinned before a live train can pass.
Contract fixtures and dry mode never count as live evidence.

`honua-devops#149` now supplies Terraform plan/apply and a secretless ECS MCP
handoff, but its handoff is not the candidate-bound full-arc receipt. The
remaining AWS producer must consume that handoff while the cell is live; this
repository will not replay Terraform to manufacture a second deployment.
