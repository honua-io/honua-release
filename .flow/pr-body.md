Apply the 2026-09-29 operator-approval review model to the release-line controls (#236)
## What this changes

The owner ruling of 2026-09-29 (https://github.com/honua-io/honua-release/issues/236#issuecomment-5883910519) replaced #236's second-human reviewer requirement for 2026.1. The control tooling still demanded it, so every audit failed on a requirement the owner had already moved to 2026.2. This PR encodes the ruling and records what is still open.

Release promise at stake: the adopted quality contract §§4.4, 10.1 and 14 requires reviewed release lines, fail-closed required checks, no unreviewed bypass, and signed native publication tags.

- **`policy.json` `review_model: operator-approval-2026.1`.** `render` now emits a release-line ruleset that still requires a pull request, the exact strict required checks (bound to GitHub Actions 15368), resolved threads, stale-review dismissal, no deletion or force push, and **no bypass actors**. It requires 0 approvals and turns code-owner and last-push approval off. The sole writer cannot approve their own PR, so those settings would block every merge instead of adding review. The operator approves by merging.
- **`audit` follows the model.** It no longer reports `no independent human code owner` under the ruling. It still requires the catch-all CODEOWNERS line naming the operator at the inspected SHA, and it requires that operator to hold write access. Live settings that are stronger (approvals, code-owner or last-push review turned on) are accepted, and weaker ones still fail. Without a `review_model`, the two-person contract applies unchanged. A model missing its `ruling`/`id`, or with a bad approval count, refuses to render. Receipts now name the review model.
- **`operator-actions`** reports the independent-owner row as `deferred` (never `satisfied`). The apply step now asks for one denied change plus one change the operator merged after every required check passed.
- **honua-demo-infra check set.** It now has its two contexts, `Terraform format and validate` and `demo-services.v1.json matches seed definitions`. Both come from `manifest-drift.yml`, which runs on every pull_request/push with no path filter, and its 8 most recent PR runs are green.
- **The other three missing check sets get specific reasons** in `check_qualification`:
  - honua-iac and honua-evidence only have path-filtered PR workflows. A release-line PR outside those paths would never report, so it could never merge.
  - The compatibility-suite repository's only always-on PR check (`contracts`) has failed on trunk and every PR since 2026-10-16 (trunk run 38873190052).
- **Fresh read-only capture.** `snapshot-2026-10-20-windows.json` and `audit-2026-10-20-windows.json` were captured with GET requests only, and no settings were changed. The audit is still **fail for all 17 repositories**:

  | Failure | Repos |
  |---|---|
  | Catch-all CODEOWNERS missing | 16 |
  | Release-line ruleset not applied | 14 |
  | Check set missing | 3 |
  | Immutable tag ruleset missing | 2 |
  | No nominated signer | 5 tag-publishing repos |

  The 2026-09-06 receipts are kept as historical. They bind the older policy bytes.
- **Vendor-term allowlist entry**, scoped to the repository-name key and API URL in the two new receipt files only.

New tests are written from the ruling and the rules-API shape, not captured from the renderer. They cover:

- the exact operator-model pull-request rule;

- acceptance of stronger live review settings;
- an operator-model ruleset still failing the default two-person contract;
- a ruling-less or malformed model refusing to render.
